# Validation & Limitations

本文记录 CompetitorAI 当前 MVP 已完成的验证范围，以及仍然存在的限制。

---

## 已完成验证

### 1. Evidence 输入

当前 MVP 使用 12 条固定的 Verified Evidence 作为输入。

已检查：

- Evidence ID 是否存在
- 输入哈希是否与预期一致
- Evidence 是否属于对应产品和比较维度
- 未使用 Unverified Evidence 补充缺失内容

固定输入主要用于保证实验可以复现，并减少搜索结果变化对测试结果的影响。

---

### 2. 输出结构

当前简报要求包含：

- ChatGPT / Claude / Gemini 三方能力对照表
- 两条基于 Evidence 的观察
- 一条明确标记为 Hypothesis 的产品设计假设
- Evidence ID
- 来源和置信度
- Evidence Gap
- 适用范围及限制

如果必要结构缺失，输出不会被标记为通过。

---

### 3. Programmatic Checks

当前实现包含以下程序化检查：

- Evidence ID 合法性
- 产品与比较维度的引用范围
- Markdown 表格结构
- 必要字段完整性
- 正文长度
- Evidence Gap 是否显式展示

正文目标长度为 1,500–2,500 字符，5,000 字符为硬上限。

---

### 4. Semantic Review

在程序检查之后，会进行一次单独的语义审查。

审查重点包括：

- Evidence 是否实际支持对应主张
- 是否存在过度概括
- 产品或套餐归属是否存在问题
- 是否遗漏重要限制
- Hypothesis 是否被误写成已验证事实

语义审查属于辅助质量控制步骤，不视为绝对事实验证。

---

### 5. 真实运行

当前 MVP 已完成一次真实简报生成和一次单独语义审查。

运行中保存了：

- 选定 Evidence
- 输入哈希
- 模型响应
- 检查结果
- 审查结果
- 提示词及对应记录
- 调用次数
- 错误和警告信息

最终候选简报正文约 1,804 字符。

---

### 6. 离线测试

当前相关离线测试共 30 项通过。

测试覆盖包括：

- 正常输入
- Evidence ID 异常
- 输入篡改
- 引用范围错误
- Evidence Gap
- 长度边界
- Markdown 表格格式
- 表格内部空行
- 错误列数
- 错误表头或分隔行
- 零模型调用重放

Ruff 检查和格式检查均通过。

---

## 实际发现并修复的问题

### Markdown 表格渲染问题

第一次真实运行中，表格行之间被插入空行。

原有检查没有发现这一问题，因此部分检查虽然通过，但最终 Markdown 表格无法按照预期展示。

后续进行了以下处理：

1. 定位表格渲染逻辑
2. 修复表格内部换行
3. 新增错误格式回归测试
4. 使用原始结构化模型结果重新渲染
5. 未再次调用模型生成内容
6. 保留原始失败记录

修复后，旧错误格式会被新的检查器拒绝，新格式可以通过检查。

## 当前限制

### 1. Evidence 不是实时数据

当前示例基于项目保存的 Frozen Evidence。

因此，项目可以验证“Evidence 到简报”的处理流程，但不能据此证明 ChatGPT、Claude 或 Gemini 当前仍保持相同的功能、套餐或地区可用性。

---

### 2. Semantic Review 仍可能漏检

语义审查可以帮助发现部分引用不支持、过度概括或归属问题，但模型审查本身并不保证发现所有错误。

因此：

**Review PASS ≠ 所有事实绝对正确。**

---

### 3. 当前验证范围较小

当前 MVP 只验证：

- 3 个产品
- 3 个能力维度
- 12 条 Verified Evidence
- 1 次真实生成流程

目前没有基于大规模人工标注评测集计算事实准确率。

---

### 4. 尚未生产化

当前项目属于可运行 MVP。

尚未按生产环境要求实现：

- 在线服务部署
- 用户账号与权限
- 运行监控
- 大规模并发
- 线上异常恢复

这些内容不属于当前版本的验证范围。

---

## 如何理解当前结果

目前的测试结果可以证明：

- 固定 Evidence 输入下，系统可以完成简报生成、程序检查和语义审查流程；
- 已知格式和引用错误可以通过对应规则识别；
- Evidence 不足可以被显式标记，而不是自动补全；
- 已发现的问题可以通过回归测试验证修复结果。

当前结果不能证明：

- 所有事实都正确；
- 系统对所有竞品研究任务都有效；
- 产品信息是最新状态；
- 系统已经达到生产级可靠性。

因此，本项目当前定位为：

**完成核心链路验证的竞品研究 MVP。**
